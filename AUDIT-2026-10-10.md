# KAB Pharma — review and update, 10 October 2026

Source: the supplied `kabpharma-store-main (7).zip`. Public site reviewed: https://www.kabpharma.com.

## التعديلات

- التسجيل وتسجيل الدخول: حاويات قابلة للتقلّص، عمود واحد صريح على الموبايل، مساحة داخلية أصغر، وحقول لا تفرض عرضاً أكبر من الشاشة. أزيل القصّ من الإطار الخارجي حتى لا يخفي المحتوى أو قائمة الدول. بقي تصميم الكمبيوتر كما هو.
- ألوان الموقع: `color-scheme: only light` في CSS وبيانات الصفحة، حتى يعلن الموقع دعمه للوضع الفاتح فقط. المتصفحات أو إضافات الوصول التي تفرض قلب الألوان قد تتجاوز ذلك؛ ليس هذا تصميماً جديداً للوضع الداكن.
- التنقّل: تحميل كامل مسبق لصفحة المنتجات من الروابط الرئيسية. إعداد كاش Next.js التجريبي `staleTimes` يعيد استخدام الصفحات المحمّلة بالكامل لمدة 60 ثانية؛ الصفحات الديناميكية غير المحمّلة مسبقاً تبقى بإعداد 0. لم تُضف ذاكرة تخزين عامة إلى APIs الخاصة بالحساب أو الطلب أو الأسعار.
- صفحة المنتجات: أول أربع صور تبدأ التحميل مباشرة؛ بقية الصور تبقى lazy. تفاصيل المنتج تُجهّز عند لمس الرابط أو المرور فوقه أو تركيزه، بدل تنزيل تفاصيل كل المنتجات تلقائياً.
- دليل العلامات: الصور تستخدم `next/image` بأحجام متجاوبة بدل الصور الأصلية غير المحسّنة.
- المساعد: رابط التسجيل يستخدم Next Link بدل إعادة تحميل الموقع كاملاً. أصلح ذلك أيضاً خطأ ESLint موجوداً بالنسخة الأصلية.
- حفظ موضع التمرير: تجميع عمليات الكتابة أثناء السحب كل 150ms بدل الكتابة مع كل إطار. يُحفظ آخر موضع قبل المغادرة، مع إبقاء مفتاح الصفحة القديمة منفصلاً عن الصفحة التالية.
- أزرار إظهار كلمة المرور وتأكيدها في تسجيل البريد أصبحت مسماة لقارئات الشاشة بالعربية والإنجليزية.

## Dependency fixes

The initial runtime dependency audit reported three vulnerable dependency entries: Next.js, Capacitor Android, and source-map-js. Updated the dependency manifest and lockfile. The final lockfile resolves Next.js 16.3.8, Capacitor Android/Core 8.4.3, and source-map-js 1.2.2. The final `npm audit --omit=dev` reports zero known vulnerabilities. This is a registry audit, not proof that the entire system is free of security issues.

Primary advisory references:
- https://github.com/advisories/GHSA-cjq9-62q9-8jv4
- https://github.com/advisories/GHSA-rvm3-566m-v7fv
- https://github.com/advisories/GHSA-68fv-2mgg-jv7q

The all-dependencies audit still reports a development-tool chain involving `braces`, `micromatch`, `fast-glob` and the Next ESLint plugin (five entries tracing to one advisory). npm proposes a breaking downgrade to eslint-config-next 14 to remove it; that downgrade was not applied. This remaining development-tool finding is documented here rather than hidden:
https://github.com/advisories/GHSA-vfj7-8cjw-p6xm

## Validation and limits

- TypeScript and whole-project ESLint: passed. ESLint retains six warnings, concerning existing back-office raw images and two unused variant parameters; these are not compilation errors.
- Scroll persistence test: passed. Covers batching many events into one final write, preserving outgoing query/route keys, flushing on departure, and cleanup without duplicate writes.
- Production build: passed (84 prerendered outputs). Performed with the repository CI's placeholder configuration. This validates compilation and route generation, not connectivity or real Supabase data. Placeholder database queries log expected failures; the resulting local build must not be deployed as a production build.
- Live public site: observed home, products, product detail, signup (phone and email tabs), brands, best sellers, about, contact, privacy policy and guest cart. The privacy page switched successfully from Arabic to English. Product pagination changed 16 cards to 32; ascending-price sorting displayed the lower-priced product first. A guest cart item priced at 130 SYP became 260 SYP for two units and was removed after the test. No order was submitted and no message/verification code was sent.
- Reviewed customer quote/COD entry points and admin authorization helpers for existing server-side pricing/session/origin checks. No production data, roles, database policies or payment provider settings were changed. This was not a penetration test or an exhaustive RLS audit.
- Actual Samsung Internet and iPhone Safari were not available. The Samsung clipping cause and iPhone image/cache behaviour cannot be conclusively verified here. The fixes address identifiable layout constraints and loading/navigation configuration; they require real-device confirmation after deployment.
- No Lighthouse score, Core Web Vitals measurement or speed percentage is claimed. The deployed site still uses its previous code until this update is published; live checks are smoke tests of that version, not measurements of this update.
- Signed-in account flows, OTP delivery, real checkout/payment, admin workflows and Android app builds were not exercised end to end.

## Apply and verify

1. Keep your existing `.env.local` and deployment secrets. Replace source files with this project, including `package.json` and `package-lock.json`.
2. Run `npm ci`, then `npm run check` with your real project configuration, and deploy through your usual workflow. No new SQL migration is required for these changes.
3. On Samsung Internet and iPhone Safari, check phone/email signup at narrow widths, large text, and with the keyboard open. Check country selection and password visibility.
4. Open Products, scroll/load more, open a product, swipe Back and navigate through the bottom tabs. Confirm the expected position and images. Revisit after the 60-second cache window and confirm stock/prices refresh appropriately.
5. Compare network requests and page/image timing before and after on the same device/network. Check normal and system dark mode; verify text, controls, logos, transparent banners and overlays.
6. With a designated test account, verify sign-in/out, OTP, wishlist, cart variants, stock changes and checkout. Use a controlled test order/payment only through your normal testing procedure.

The existing banner layout, marquee, product ordering, catalog pagination sizes, pricing calculator and SQL files are preserved.
